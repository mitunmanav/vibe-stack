# New commands

Vibe Stack does not add a command for behaviour that composes from the existing ones. Requests for new commands are judged against `SCOPE.md` like any other change, and most do not clear it.

## Why this is out of scope

Every command is something the user has to remember. The people Vibe Stack serves are already learning a new way of working, and each extra command makes "which one do I type?" harder. That is the cost `/what-next` exists to pay down, and it grows with every command.

Every command is also permanent upkeep: it has to stay in step with the others, with its docs page, with the flow map, and with both plugin manifests. The fewer and shorter the commands, the cheaper they are to keep correct.

Most proposals are a workflow built from existing pieces: an interview, a plan, a build, a repair. That composition belongs in your own prompts.

A new command that does clear the bar starts as beta.
