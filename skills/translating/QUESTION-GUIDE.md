# Wording Questions for the User (`QUESTION-GUIDE.md`)

Ask about the world the user already knows: people, screens, buttons, money, and time. Under every technical question sits an everyday one; ask that one.

| The technical question | Ask this instead |
| :--- | :--- |
| How pieces of data relate | A story: "Can one person book for several friends at once, or one spot each?" |
| Where data is kept | "Will this be used on this one computer, or on several phones and computers?" |
| How people sign in | A one-way door: "Start with a simple passcode on this computer (free), or set up Google sign-in now?" |
| Whether to use a paid outside service | A one-way door with the price, recommending a free stand-in first. |

If a technical word slips into a draft question, rewrite the question rather than explaining the word. Keep each question to one decision.

## A sheet for someone else

When only another person can answer, ask the user in one round who that person is and what the user needs back from them. Then write `.vibe/questions-for-<name>.md`:

1. One short paragraph of context for a reader who was not in this chat.
2. The questions, most important first, each about one thing, with space to answer under it.
3. A line saying "I'm not sure" is a useful answer.
4. A closing question: "Is there anything we should have asked?"

Done when every item the user needs back has a question on the sheet. Tell the user where the file is.
